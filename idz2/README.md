# АКОС · ИДЗ №2 · Вариант 34

Многопоточный сортировочный центр посылок: C11, POSIX, pthread, мьютекс и семафоры.
Нужны компилятор C и Make; для автотестов - Python 3.

## Сборка и запуск

```sh
make
./build/sorting_center
./build/sorting_center --help
./build/sorting_center --parcels 30 --delay-ms 100 --log run.log
```

Для каждой посылки, входной линии, сканера, сортировщика и конвейера создаётся отдельный поток.
Число посылок - от 0 до 512, число устройств каждого вида - от 1 до 64.
На каждое направление выделены конвейер, выходной накопитель и поток разгрузки.

Без аргументов обрабатываются 20 посылок. `--delay-ms` задаёт длительность единицы
модельного времени; при 0 искусственные задержки отключены. `--seed` повторяет
направления и результаты чтения каждой посылки, но порядок строк и время выполнения
зависят от планировщика ОС. `--check` включает полный контроль инвариантов после событий.

После доставки всей партии или передачи на ручную обработку программа завершается сама.
Ctrl+C и SIGTERM останавливают ожидающие потоки и сохраняют частичную статистику.
Коды выхода: 0 - завершение, 1 - ошибка выполнения, 2 - неверные аргументы, 130/143 - прерывание.

## Проверка

```sh
make test
sh tests/demo.sh
```

Для проверки на целевой ОС Linux, с установленными GCC/Clang, Make и Python 3:

```sh
sh tests/linux.sh
```

В сценарий включены AddressSanitizer, UndefinedBehaviorSanitizer и ThreadSanitizer.
Отдельно их можно запустить командами `make sanitize` и `make tsan`.
Тестовая сборка `sorting_center_fault` искусственно вызывает отказ `pthread_create`;
основная программа такой подмены не содержит.

Под Linux используются `sem_init/sem_destroy`, под macOS - `sem_open/sem_close`
с немедленным удалением имени семафора. Алгоритм и взаимодействие потоков одинаковы.
Результаты фактических проверок и ограничения приведены в отчёте.
