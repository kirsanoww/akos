## Быстрая проверка через Docker

Из этой папки, при запущенном Docker Desktop:

```sh
docker build -t akos-idz4 .
docker run --rm --init akos-idz4 make test
docker run --rm --init akos-idz4 make sanitize
docker run --rm --init -it akos-idz4 python3 scripts/run_demo.py --delay-ms 30 --check
```

Демонстрация запускает сервер, 13 рабочих клиентов и двух наблюдателей.
Сервер выводит события в терминал, вывод клиентов сохраняется в `logs/` контейнера.
Для сохранения журналов на компьютере:

```sh
mkdir -p logs
docker run --rm --init -it --mount "type=bind,source=$(pwd)/logs,target=/project/logs" \
  akos-idz4 python3 scripts/run_demo.py --delay-ms 30 --check --log logs/server.txt
```

Проверка связи между тремя отдельными Linux-контейнерами:

```sh
python3 tests/distributed.py
```

## Linux: отдельные терминалы

```sh
make
```

Терминал 1 - сервер:

```sh
./build/center_server 127.0.0.1 9034 --delay-ms 30 --check --log events.txt
```

Терминалы 2 и 3 - независимые наблюдатели:

```sh
./build/center_observer 127.0.0.1 9034
```

Терминал 4 - рабочие клиенты:

```sh
python3 scripts/run_workers.py 127.0.0.1 9034
```

Каждого участника можно запустить вручную, например:

```sh
./build/center_worker 127.0.0.1 9034 scanner 1
```

Не запускайте вторую копию занятой роли. При ручном запуске создайте все роли
из строк `PLAN` сервера: по умолчанию source 1..2, scanner 1..2, sorter 1..2,
belt 1..3 и unload 1..4. Последний разгрузчик обслуживает ручной накопитель.
Сервер начинает обработку после подключения первоначального полного набора.
Наблюдатели для старта не обязательны.

## Несколько компьютеров

На Linux-сервере укажите его IPv4 или `0.0.0.0` для прослушивания всех интерфейсов.
На остальных компьютерах укажите доступный IPv4 сервера и тот же порт, например:

```sh
./build/center_server 0.0.0.0 9034 --delay-ms 30 --check
./build/center_observer 192.168.1.10 9034
./build/center_worker 192.168.1.10 9034 scanner 1
```

`192.168.1.10` заменяется адресом вашего сервера. Нужна доступность выбранного TCP-порта.
Общих каталогов, shared memory и общего родительского процесса не требуется.
Если сервер работает в Docker, опубликуйте порт: `-p 9034:9034`, а внутри слушайте `0.0.0.0`.
Программа принимает числовые IPv4-адреса, без DNS и IPv6.

## Параметры и завершение

`./build/center_server --help` выводит параметры. Сохранены параметры ИДЗ3:
число посылок и направлений, устройства, очереди, времена, ошибки, повторы,
`--seed`, `--delay-ms`, `--check`, `--log`. Партия: 0..512, устройства: 1..16 каждого вида.
Вместимости выше 512 эквивалентны 512, поскольку партия не может быть больше.

`--startup-timeout N` - предел ожидания прогресса без выполняющегося задания,
по умолчанию 30 секунд. Он действует и при отсутствии обязательных участников,
и после разрыва соединения. Для длительной демонстрации переподключения установите 300.
Законная обработка с большой задержкой не считается простоем.

Рабочего клиента можно остановить Ctrl+C и запустить с той же ролью и номером.
Незавершённое задание остаётся у сервера, после возврата задержка этого задания
отсчитывается заново. Если результат уже принят, повторно он не применяется.
Остальные участники продолжают работать до заполнения зависимых очередей.

Клиент автоматически повторяет подключения после сетевого разрыва в течение
`--retry-seconds N` секунд (по умолчанию 10, 0 отключает повторы).
Heartbeat обнаруживает молчащее соединение за 5-6 секунд.
Наблюдатель после каждого подключения получает свежий снимок всей модели,
затем последовательный поток событий. Старый журнал при подключении не воспроизводится.

После обработки партии сервер отправляет итог и `STOP complete` всем подключённым
клиентам. Ctrl+C/SIGTERM сервера отправляют `STOP signal` с частичной статистикой.
Коды сервера: 0 - успех, 130/143 - сигнал, 1 - ошибка/простой, 2 - аргументы.
Клиент возвращает 0 при полученном STOP, 130/143 при своём сигнале, 1 при потере
сервера без восстановления, 2 при неверных аргументах. Причина остановки видна в STOP.
После SIGKILL сервер не может послать STOP; клиенты обнаружат разрыв и завершатся
после срока повторов. Восстановление состояния после гибели самого сервера не реализовано.

Основной код не использует Python. Python нужен только для тестов и удобного запуска
нескольких независимых C-программ. На сдачу включены исходники и готовый PDF;
программы собираются командой `make`.
